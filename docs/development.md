# Порядок разработки PassGo

## Структура и ответственность

Даниил ведёт backend и infra: сервер, базу, миграции и развёртывание. Максим ведёт frontend: экраны, запросы к серверу и сканер. В docs хранятся общие требования и решения. Документы Word сохраняются в папке проекта и прикрепляются к соответствующей задаче Ёжки.

backend/requirements.txt содержит основные серверные библиотеки. requirements-dev.txt добавляет инструменты проверки. frontend/package.json содержит начальный набор клиентских библиотек. Папка infra предназначена для Docker Compose и настройки HTTPS; в S1-07 она содержит описание назначения, а рабочая конфигурация появится в S1-08 и S1-14.

## Окружение и зависимости

Для сервера используется Python 3.12, для интерфейса — Node.js 22 начиная с 22.12.0. PostgreSQL 17 выбран как основная версия базы; конкретный образ закрепляется при настройке Compose в S1-08. Django 5.2 выбран как LTS-ветка.

Основные зависимости закреплены точными версиями без latest, ^ и ~. При создании рабочего каркаса проверяются установка и запуск. В S1-08 закрепляется полный набор серверных зависимостей, в S1-11 создаётся и коммитится package-lock.json с транзитивными зависимостями; после этого клиент устанавливается через npm ci. Сейчас наличие списка библиотек не означает готовую сборку.

QR-библиотека, графики и библиотеки запросов добавляются в задачах, где они используются. Не устанавливаем весь планируемый стек заранее. Изменение версии зависимости оформляется отдельным изменением с причиной и проверкой совместимости.

Для будущего Compose скопировать корневой .env.example в .env и заполнить DJANGO_SECRET_KEY и POSTGRES_PASSWORD локально. POSTGRES_HOST=db предназначен для контейнера; при запуске Django вне контейнера потребуется localhost. В production DJANGO_DEBUG=false, разрешённые хосты и доверенные CSRF-адреса задаются явно с HTTPS.

Для будущего Vite скопировать frontend/.env.example в frontend/.env. VITE_API_BASE_URL является публичным адресом API. Клиентские переменные попадают в сборку, поэтому пароли и ключи там не хранятся. До настройки каркаса примеры окружения не подключены к приложению.

## Ветки и коммиты

main хранит проверенные изменения. Для задачи создаётся ветка feature/s1-08-backend-bootstrap; для исправления — fix/s1-08-health-response. Перед началом обновляем main, затем создаём ветку. Не включаем в один запрос на объединение несвязанные задачи.

В сообщении коммита указываем код и действие: S1-08 Добавить проверку состояния сервера. В описании запроса на объединение указываем ссылку на карточку, результат, выполненные проверки и известные ограничения. Коммиты и ветки не подменяют фиксацию результата в Ёжке.

## Взаимная проверка

Изменения Даниила проверяет Максим, изменения Максима — Даниил. Проверяющий читает изменения, воспроизводит применимые проверки и оставляет результат в запросе на объединение. После устранения замечаний изменение объединяется в main. Одобрение документа не означает, что код уже протестирован.

Результат задачи прикрепляем к карточке или указываем ссылкой. Чеклист отмечаем по фактической готовности; задачу закрываем после выполнения критериев и проверки вторым разработчиком. Время и результаты проверок не придумываем.

## Критерии готовности изменения

1. Изменение выполняет требования своей карточки и не добавляет несогласованный объём.
2. Другой разработчик проверил результат; замечания исправлены или согласованы.
3. Для кода выполнены применимые проверки: конфигурация, миграции, тесты, типы и сборка. Команды добавляются вместе с каркасами; отсутствие запуска записывается как ограничение.
4. Для документа сверены правила, поля и ссылки с соседними решениями.
5. В Git нет секретов, реальных билетов, персональных данных участников, локальной базы и файлов окружения.
6. Инструкции соответствуют фактическому состоянию проекта; ссылки на результат добавлены в карточку.

## Текущее состояние

S1-07 подготавливает структуру, шаблоны окружения, начальные зависимости и порядок работы. Django, Docker Compose и React пока не созданы. Рабочий запуск и проверки сборки относятся к следующим задачам. Перед публикацией этого набора файлов требуется проверка Максимом.
